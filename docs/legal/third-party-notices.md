## How this list was made

The Rust crate tables were produced on 2026-10-30 from `Cargo.lock` at commit `83950ee`, with cargo 1.98.1. To regenerate them after a dependency change, run this from the repository root:

```sh
cargo metadata --format-version 1 --filter-platform x86_64-unknown-linux-gnu > /tmp/dfte-linux.json
cargo metadata --format-version 1 --filter-platform aarch64-linux-android > /tmp/dfte-android.json
python3 docs/legal/gen_third_party.py /tmp/dfte-linux.json /tmp/dfte-android.json
```

The script rewrites only the section between the `crates:begin` and `crates:end` markers. It counts a crate when the shipped program actually contains it: anything reachable from `dfte-cli` and `dfte-gtk` (Linux) or `platform-ffi` (the Android library) through normal dependencies. Build scripts, proc-macro crates and dev-dependencies only run on the build machine, so they are left out. The license is the one each crate declares in its `Cargo.toml`. `cargo deny check licenses` (configured in `deny.toml`) checks the same declarations against the project's allow-list.

The other sections (Android libraries, fonts, Linux system libraries) were written by hand from `platform/android/app/build.gradle.kts`, `platform/android/third_party/` and `platform/linux/Cargo.toml`. Update them when those files change.

## License texts and copyright lines

Most of these licenses (MIT, BSD, ISC, Zlib, Apache-2.0) ask that a binary distribution include the license text and the authors' copyright notice. Every crate carries both in its source package, which Cargo downloads to `~/.cargo/registry/src/`. This file does not reproduce them one by one yet. Before a public release, the full texts should be collected into a file that ships with each app (`cargo about generate` can do this from the same data) and shown in an "Open-source licenses" screen.

## Rust crates

A few entries need a note:

- `ring` is under Apache-2.0 and ISC together, not a choice between them. Parts of it come from BoringSSL and OpenSSL. Both licenses apply.
- The `uniffi` crates (MPL-2.0) are used unmodified. MPL-2.0 covers changes to those files only, and their source is at https://github.com/mozilla/uniffi-rs. If we ever patch them, the patched files have to be published under MPL-2.0.
- The Android list includes `uniffi_bindgen`, `askama`, `toml`, `goblin` and similar crates. They are there because `uniffi` turns on its `cargo-metadata` feature by default, which makes the binding generator a normal dependency. Most of that code is probably removed by the linker, but the list includes it to be safe.
- `curve25519-dalek`, `ed25519-dalek` and `subtle` are BSD-3-Clause. That license forbids using the authors' names to promote DFTE without permission.
- For crates offered under a choice of licenses ("A OR B"), DFTE may use any one of them.

The Rust standard library, which is compiled into every binary, is under MIT OR Apache-2.0.

## Fonts

The Android app bundles three font files in `platform/android/app/src/main/res/font/`. Both fonts are under the SIL Open Font License, version 1.1. The full license text, with the copyright line, is in `platform/android/third_party/Inter-OFL.txt` and `platform/android/third_party/JetBrainsMono-OFL.txt`, and has to be shipped with the app.

- Inter (`inter_regular.ttf`, `inter_semibold.ttf`). Copyright (c) 2016 The Inter Project Authors (https://github.com/rsms/inter).
- JetBrains Mono (`jetbrains_mono_regular.ttf`). Copyright 2020 The JetBrains Mono Project Authors (https://github.com/JetBrains/JetBrainsMono).

The OFL allows bundling the fonts with software. It doesn't allow selling the font files on their own. Neither license file names a Reserved Font Name. The Linux app does not bundle any fonts. Its style sheet asks for Inter and JetBrains Mono and uses them only if they are already installed on the system.

## Linux system libraries

The Linux desktop app, `dfte-gtk`, uses GTK 4 and libadwaita through the `gtk4-rs` and `libadwaita-rs` binding crates (MIT, listed above). The libraries themselves are not part of DFTE. They are installed by your distribution (or by the Flatpak runtime) and loaded at run time as shared libraries:

| Library | License |
|---|---|
| GTK 4 | LGPL-2.1-or-later |
| libadwaita | LGPL-2.1-or-later |
| GLib, GObject, GIO | LGPL-2.1-or-later |
| Pango | LGPL-2.1-or-later |
| GdkPixbuf | LGPL-2.1-or-later |
| Cairo | LGPL-2.1 or MPL-1.1 |
| Graphene | MIT |

Because DFTE links to these libraries dynamically and does not modify or ship them, you can replace them with your own builds of compatible versions and DFTE will use them. If a future package does bundle them (an AppImage, for example), it must include their license texts and say where their source code can be obtained.

The command-line app `dfte` does not use GTK. With `--wifi-direct` it talks to NetworkManager, which runs as a separate system service, over D-Bus. Both the CLI and the GTK app link against the system C library.
